# Web overview <span class="badge-new">NEW</span>

The **web** app is a React 19 + Vite SPA that lives in `apps/web/`. It
fetches all data from the API over HTTPS and subscribes to Supabase
Realtime for live Kanban updates. The build is containerized via
`apps/web/Dockerfile` and served as static files by Railway.

## Key directories

```
apps/web/src/
├── components/    # Reusable UI primitives (Button, Modal, Markdown…)
├── hooks/         # React hooks (useProjects, useTicket, etc.)
├── lib/           # Non-React utilities (clientId, supabase client)
└── views/         # Route-level view components
```

## Realtime suppression

Every mutating action the web app makes includes an `x-client-id` header
containing a per-tab UUID (generated by `apps/web/src/lib/clientId.ts`).
When a Supabase Realtime broadcast arrives, hooks like `useTicket` compare
the payload's `updated_by_client` field against the local `CLIENT_ID`; if
they match, the update is ignored because the optimistic state already
reflects the change.

This prevents "double-updates" where a user edits a ticket and then sees
the same change applied again a moment later when the broadcast comes back.

## Routing

The SPA uses `react-router-dom` for client-side routing. Key routes include:

| Route                             | View component        | Purpose                     |
|-----------------------------------|-----------------------|-----------------------------|
| `/`                               | `BoardView`           | Kanban board (projects)     |
| `/projects/:projectId`            | `ProjectDetailView`   | Project tickets Kanban      |
| `/projects/:projectId/tickets/:ticketId` | `TicketDetailView` | Full-page ticket detail |

See [Ticket Detail View](./ticket-detail-view.md) for coverage of the
ticket detail page.
